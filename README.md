# AstrBot 插件：TTS 情绪标签注入

让 AI 的回复"开口有表情"——通过向语音合成文本注入 MiniMax 表演标签，让机器人说话带轻笑、笑声、叹气、换气等真实情绪，同时保证发送给用户看的文字永远干净。

## 简介

这是一个 AstrBot 插件。它利用 MiniMax `speech-2.8` 系列模型支持的**表现标签**（如 `(chuckle)`、`(laughs)`、`(sighs)`、`(breath)`），在 LLM 生成的回复文本中注入这些"表演指令"，从而让合成的语音具有真人般的语气变化。同时，插件会从发送给用户的纯文本中剥离所有标签，避免聊天中出现 `(chuckle)` 之类的标记。

## 核心流水线

```
LLM 请求
  └─ on_llm_request  向系统提示注入"表现标签使用约定"（软约束）

LLM 回复
  └─ on_llm_response 强制规范化标签（识别->归一化->非法丢弃）

发送前
  └─ on_decorating_result
        ├─ 接管模式：按触发概率合成带表演语音 + 保留干净文本
        └─ 非接管模式：仅剥离标签，回归 AstrBot 原生 TTS
```

## 功能

- **自动注入表现标签**：LLM 根据语义在合适位置输出 `(chuckle)` / `(laughs)` / `(sighs)` 等表演指令。
- **正则兜底注入**：当 LLM 没有主动写标签时，插件会根据场景关键词兜底注入一个最贴切的表情（如"好耶"→`(chuckle)`、"呜呜"→`(sighs)`），受 `insert_probability` 概率与 `max_tags_per_message` 上限控制，克制不喧宾夺主。
- **强制规范化**：无论 LLM 输出多乱（中文括号、大写、驼峰、错写、别名），插件都会把它们归一化成 MiniMax 认可的标准英文小写标签；无法识别的**一律丢弃**，绝不喂给 TTS，避免 MiniMax 报错。
- **剥离 QQ 文本标记**：超宽兜底剥离所有括号标签与 `<#0.35#>` 停顿指令，保证发送给用户的文字永远干净。
- **触发概率控制**：只有命中 `trigger_probability` 概率的回复才会转成语音，其余保持纯文本，避免"每条都变语音"。
- **文本始终保留**：即使命中概率转成语音，也会**同时输出干净的纯文本**（语音 + 文字双输出）。

## 安装

1. 将本插件目录放置在 AstrBot 的 `data/plugins` 目录下。
2. 确保 `metadata.yaml` 配置正确。
3. 在 AstrBot WebUI 的**插件管理**中启用该插件，或重启 AstrBot。

> 注意：要获得带表演的语音，你需要已经配置好一个 TTS Provider（推荐 MiniMax `speech-2.8` 系列，因为只有这些模型支持表现标签）。插件复用的是 AstrBot 已配置的 TTS Provider。

## 配置

在 AstrBot 的 WebUI 插件管理面板中支持配置以下项：

- **接管 TTS 合成 (`enable_tts_takeover`)**：布尔开关，默认开启。
  - 开启：按触发概率将部分回复转成带表现标签的语音（同时保留文本）。
  - 关闭：插件完全放手，回归 AstrBot 原生 TTS 行为（无表演）。
- **触发概率 (`trigger_probability`)**：浮点数，默认 `0.3`（约 30% 的回复转语音）。
  - 仅接管模式生效。值越大越容易把回复转成语音；`0` 表示永不转语音，`1` 表示全部转语音。
- **QQ 文本标签剥离 (`enable_strip`)**：布尔开关，默认开启。
  - 接管模式关闭时，是否从发送给用户的消息中移除表现标签。

## ⚠️ 重要：内置 TTS 配置（务必按此设置）

本插件通过 AstrBot 的 `get_using_tts_provider_async()` 获取 MiniMax 合成器。该接口在 **「启用文本转语音」总开关关闭时，会直接返回 `None`**，导致插件拿不到 provider、无法合成语音。

因此，请**务必按以下方式配置** AstrBot 内置 TTS：

- **「启用文本转语音」总开关**：✅ **保持开启**
- **「TTS 触发概率」**：设为 **`0`**

> 为什么这样设？
> 1. 总开关开启 → 插件能通过接口拿到 MiniMax provider，正常接管合成。
> 2. 内置触发概率设为 `0` → AstrBot 内置 TTS 永远不主动合成，不会跟插件抢、不会产生"双重/多条语音"。
> 3. 最终效果：语音完全由**本插件**控制（用插件自己的 `trigger_probability`），内置 TTS 只是"让 provider 可用"而已。

### 配置对照表

| 场景 | 内置「启用文本转语音」 | 内置「TTS触发概率」 | 插件 `enable_tts_takeover` | 插件 `trigger_probability` |
|------|:---:|:---:|:---:|:---:|
| **使用本插件（推荐）** | ✅ 开 | **0** | ✅ 开 | 按需（如 `0.3`） |
| **回归原生 TTS** | ✅ 开 | 按需（如 `1`） | ❌ 关 | 忽略 |

> 一句话：**用插件时，内置 TTS 保持开启但概率设为 0，让插件全权接管**；不用插件时，把插件 `enable_tts_takeover` 关掉即可回归原生。

### 内置 TTS 开关位置

在 AstrBot WebUI 的「文本转语音（TTS）总开关」设置中，将「启用文本转语音」设为**开启**，并把「TTS 触发概率」设为 **0**。

## 备注

- 表现标签仅出现在"喂给 TTS 的文本"中，发送给用户的文字消息一律被剥离，不会破坏聊天体验。
- 由于 `system_prompt` 只是软约束，插件通过**强制规范化**兜底，无论 LLM 输出格式多么不标准，都能保证 TTS 只收到合法标签、用户文字永远干净。
